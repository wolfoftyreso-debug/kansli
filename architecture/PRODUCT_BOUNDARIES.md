# Product boundaries

KANSLI exists to standardize conventions and provide shared foundations **without** absorbing product domain logic.

## KANSLI can own

- shared identity
- organizations
- memberships
- shared authentication conventions
- shared design tokens
- shared UI primitives
- logging conventions
- deployment conventions
- infrastructure modules
- AI provider abstraction
- notification adapters
- shared technical contracts

## Each product owns

- domain model
- business rules
- workflows
- product prompts
- product database
- product-specific integrations
- product-specific UI
- product-specific automation
- domain-specific audit events
